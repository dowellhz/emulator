# PlayStation 光盘包 `FCPS1PK1`（`.fcps1`）

一张 PS1 光盘在资料库里是**一个文件**：CUE 表和它引用的全部 BIN 依次存进同一个包，客户端整体下载、
按游戏 SHA-256 缓存，核心直接按包内偏移读扇区（`FCPS1Disc.c`）。这沿用资料库"一个游戏一个文件"的
清单、续传和校验链路，与 CPS3 的 `.fcc3`、Neo Geo 合并 set 同一思路。所有整数为小端。

| 偏移 | 类型 | 内容 |
| --- | --- | --- |
| 0 | 8 bytes | ASCII `FCPS1PK1` |
| 8 | u32le | 格式版本 `1` |
| 12 | u32le | 文件数 N（1–99） |
| 16 | u32le | CUE 文本长度 C（1–65536 字节） |
| 20 | u32le | 必须为 0 |
| 24 | N × 64 bytes | 文件表，见下 |
| 24 + 64N | C bytes | CUE 文本（UTF-8，不含 NUL） |
| 之后 | | 各文件数据 |

文件表每项 64 字节：文件名 48 字节（UTF-8，NUL 补齐，非空，同一包内不重名）、u64le 偏移、u64le 长度。
偏移不得小于 `24 + 64N + C`，偏移加长度不得超出包；长度必须是 2352 的正整数倍（原始扇区）。CUE 里的
`FILE "名字" BINARY|MOTOROLA` 只能引用表里的名字，不能指向包外。轨道格式支持 `AUDIO`、`MODE1/2352`、
`MODE2/2352`，以及 `INDEX 00/01`、`PREGAP`、`POSTGAP`、`FLAGS`。

**规范形式**（服务器和 `FCEmulatorMac/Scripts/ps1-pack-disc.py` 都按此打包，同一份 dump 总是得到同一
个包、同一个 SHA-256）：文件按 CUE 中 `FILE` 出现的先后命名为 `01.bin`、`02.bin`…；CUE 文本把这些
`FILE` 行改写成 `FILE "NN.bin" BINARY`（或 `MOTOROLA`），换行统一为 LF，去掉行尾空白和末尾空行、文件以一个
LF 结尾，其余行（含 REM）原样保留；数据紧接 CUE 文本、按文件表顺序连续存放。

包里不放 BIOS、记忆卡或存档。光盘的区码（SCEA/SCEE/SCEI）由客户端核心从包内容推断，不写进包。

固定向量：CUE 文本 `FILE "fixture.bin" BINARY` / `  TRACK 01 MODE2/2352` / `    INDEX 01 00:00:00`
（CRLF 换行）加 2 个全零扇区（4704 字节）的 `fixture.bin`，规范包共 4857 字节，SHA-256 为
`7695ddb80b43301d0930cada8b948d8460ecd27202ce31dc31bbde49bdea39dd`，前 0x58 字节为：

```text
46435053 31504b31 01000000 01000000 41000000 00000000
30312e62 696e0000 ...（文件名补零至 48 字节）
99000000 00000000 60120000 00000000
```

即 1 个文件、CUE 65 字节，`01.bin` 偏移 0x99、长度 0x1260。

## 版本 2：多碟游戏

多碟游戏（最多 8 张）的全部光盘放进**同一个包**，仍是"一个游戏一个文件"：存档、下载、校验都按整包的
SHA-256，换盘不换游戏。与版本 1 的不同只有三处：

| 偏移 | 类型 | 内容 |
| --- | --- | --- |
| 8 | u32le | 格式版本 `2` |
| 16 | u32le | 全部 CUE 文本的总长度 C（各盘 1–65536 字节） |
| 20 | u32le | 光盘数 D（2–8）；版本 1 此处为 0，表示一张 |
| 24 + 64N | D × u32le | 各盘 CUE 文本的长度，依盘序；总和必须等于 C |
| 24 + 64N + 4D | C bytes | 各盘 CUE 文本依盘序首尾相接 |
| 之后 | | 各文件数据，偏移不得小于 `24 + 64N + 4D + C` |

文件表是全游戏共用的：第 1 张盘的文件编号从 `01.bin` 起，后一张盘接着前一张盘的最后一个号继续（例如
第 1 张盘 `01.bin`，第 2 张盘 `02.bin`、`03.bin`），每张盘的 CUE 只引用自己的文件。规范形式的其余规则与版本 1
相同；只有一张盘时必须写成版本 1。每张盘的第一轨都必须是数据轨，单张盘的数据不超过 1 GiB，整包不超过 4 GiB。
上传的压缩包里每张盘一个 `.cue`（或每张盘一个 CD `.chd`），盘序取路径的自然排序（数字按数值比较，`Disc 2` 在 `Disc 10` 之前）。
CHD（单独上传即一张盘）由服务端解成每轨一个 BIN，CUE 取 `chdman extractcd` 的写法（`INDEX 00`/`INDEX 01` 表示文件内的
pregap，`PREGAP` 表示不在文件里的），再按本节规则打包；因此一轨一个 BIN 的 dump 从 CHD 打出的包与从原 cue/bin 打出的
SHA-256 相同，所有轨在同一个 BIN 里的 dump 则会拆成每轨一个文件。

核心开机插入第 1 张盘；游戏要求换盘时，玩家在暂停菜单里"换盘"：光驱盖打开约 1.5 秒（游戏读到开盖状态），
再合上换成下一张，与 Mednafen 的 `CDInsertEject`/`SetDisc` 相同。即时存档记录光驱盖状态和当前是哪张盘。

固定向量：两张盘，CUE 分别为 `FILE "disc1.bin" BINARY` / `  TRACK 01 MODE2/2352` / `    INDEX 01 00:00:00`
与同样引用 `disc2.bin` 的一份（CRLF 换行），两个文件各 2 个全零扇区（4704 字节）。规范包共 9698 字节，SHA-256 为
`477908f29995404412e9d2902fe16b9ed1b37f89e978fcd9f1149154626ff53f`；头部为版本 2、2 个文件、CUE 共 0x82 字节、
2 张盘，`01.bin` 偏移 0x122，`02.bin` 偏移 0x1382，各盘 CUE 长度 0x41、0x41。

## LibCrypt 子通道记录（`.sbi`）

部分欧版游戏用 LibCrypt 防拷贝：压盘时故意写坏某些扇区的子通道 Q，普通 dump 丢了这些数据，需要配套的 `.sbi` 文件。
包里可以为第 NN 张盘放一个名为 `NN.sbi` 的文件（`01.sbi`…`08.sbi`），排在全部轨道文件之后、按盘序，数据同样紧接前一个文件。
它不受“2352 的整数倍”限制，内容就是标准 SBI：ASCII `SBI` 加一个 0 字节，随后每条 14 字节——BCD 绝对 MSF 3 字节、
类型 `01`、子通道 Q 的前 10 字节；文件长度为 4 + 14k（1 ≤ k ≤ 4096）。读到所列扇区时，驱动看到的 Q 就是这 10 字节加上
**取反**的 CRC（Mednafen `CDAccess_Image_LoadSBI`）。打包时与 CUE 同名的 `.sbi`（扩展名大小写均可）自动收入，
格式不对则拒绝打包；核心遇到格式不对的 `NN.sbi` 拒绝打开整张盘。没有 `.sbi` 的包与以前逐字节相同。

CloneCD 镜像（`.ccd`/`.img`/`.sub`）上传时，`.img` 按 `.ccd` 的 `[TRACK n]` 切成每轨一个文件（音轨从 INDEX 00 起，
与 Redump 一致），`.sub` 中 Q 校验和错误的扇区写成该盘的 `NN.sbi`；其余子通道帧由驱动按 CUE 自行生成，不保留。
